# AI 학습

업로드된 창작 게임으로 AI를 자동 학습시키는 파이프라인입니다. 설계 배경은
[docs/architecture.md](../docs/architecture.md#ai-학습-예정)에 있습니다.

지금은 **첫 단계**입니다. 게임 폴더 하나를 내 컴퓨터에서 학습시키고, 작은 게임이면 완전 탐색한 정답으로 채점합니다.
학습한 신경망을 ONNX로 내보내 사이트에 올리면 브라우저에서 AI와 둘 수 있습니다 ([브라우저에서 AI와 두기](#브라우저에서-ai와-두기)).
서버에서 학습하기는 아직입니다 ([남은 일](#남은-일)).

## 방식: AlphaZero (신경망 + MCTS 자기대국)

PPO는 쓰지 않습니다. 승패 하나만 보상으로 받고 수읽기를 못 해서 바둑·체스 같은 게임에서 약하기 때문입니다.
AlphaZero는 같은 설정으로 여러 게임을 학습시킬 수 있는 범용 방식이고, 작은 게임에도 그대로 통합니다.

```
자기대국 (MCTS로 매 수 탐색)
  → (국면, 탐색이 고른 수의 분포, 최종 승패) 를 학습 데이터로 저장
  → 신경망 학습: 정책(어디에 둘지) + 가치(누가 유리한지)
  → 새 신경망으로 다시 자기대국
```

## 해 보기

Node 18 이상과 Python 3.10 이상이 필요합니다. 틱택토 크기는 CPU로 충분합니다.

```bash
pip install -r trainer/requirements.txt
python trainer/train.py games/tictactoe --minutes 5
```

반복마다 자기대국 결과와 손실을, 5번마다 평가를 찍습니다. 결과는 `trainer/runs/<게임 id>/`에 남습니다 (깃에는 안 올라감).

- `model.pt`: 마지막 신경망과 설정. `--resume`으로 이어서 학습합니다.
- `log.jsonl`: 반복마다 자기대국 통계, 손실(학습 중, 새 판), 평가

```
tictactoe: 3x3 board, 9 actions, 14 input channels, lang ko, device cpu
solved exactly (16168 positions): draw with perfect play
iter   1  first/second/draw 65/20/15  moves 6.8  loss p 1.554 v 0.336  buffer 682  10s
...
iter  41  first/second/draw 22/2/76  moves 8.4  loss p 0.836 v 0.110  buffer 16570  361s
final evaluation
  vs random  first W/D/L 19/1/0  second 15/5/0
  vs perfect first W/D/L 0/20/0  second 0/20/0
  best move (9105 positions)
    policy 94.4% (missed wins 438, blunders 74)
    search 99.0% (missed wins 84, blunders 7)
```

**손실** (p는 정책, v는 가치)
- `loss`: 이번 반복에서 버퍼의 판으로 학습한 손실. 같은 판을 여러 번 학습하면 판을 외워서 낮아지기도 합니다.
- `new games … (always 0: …)`: 이번 반복에 새로 둔 판을 학습에 넣기 전에 잰 손실. 신경망이 처음 보는 판이라 외운 것이 섞이지 않습니다.
  `always 0`은 가치를 늘 0이라고 답할 때의 손실입니다. 새 판의 `v`가 이보다 낮아야 승패를 조금이라도 맞히는 것입니다.
- `loss`가 `new games`보다 한참 낮으면 외우고 있는 것입니다. 한 국면을 학습하는 횟수는 대략
  `--steps × --batch ÷ 반복마다 새로 생기는 국면 수`라서, `--steps`를 줄이거나 `--games`를 늘리면 덜 외웁니다.

**평가**
- `vs random`: 아무 수나 두는 상대와 둔 결과. AI가 선공일 때와 후공일 때의 승/무/패입니다.
- `vs perfect`: 완전 탐색한 정답대로 두는 상대(가장 좋은 수 중 아무거나). 틱택토라면 모두 무승부가 나와야 완벽합니다.
- `vs rollout`: 학습 없는 롤아웃 AI(`--rollout-sims`번 탐색. 각 수 뒤를 아무렇게나 끝까지 둬 보고 고름). 마지막 평가에서만 둡니다.
  신경망 없이 공짜로 만드는 AI라서, 학습한 AI는 적어도 이 상대를 이겨야 학습한 보람이 있습니다.
- `best move`: 가장 좋은 수가 따로 있는 모든 판에서 AI가 그 수를 고르는 비율. `policy`는 신경망만, `search`는 탐색까지 한 것입니다.
  틀린 수는 이길 판을 비기거나 진 것(`missed wins`)과 지지 않을 판을 진 것(`blunders`)으로 나눕니다.
  상대가 엉망으로 둔 뒤의 판까지 모두 셉니다.
- `vs perfect`와 `best move`는 판 수가 상한(`--solve-limit`, 5만) 아래라 완전 탐색이 되는 게임에만 나옵니다.
- AI가 진 판은 `lost to …: actions …`로 행동 번호를 찍습니다.
- 학습한 신경망을 다시 평가하려면 `--eval-only`를 씁니다. `--sims`를 바꾸면 생각 시간에 따라 얼마나 강해지는지 봅니다.

**틱택토 결과** (CPU 8코어, 기본값으로 6분)
- 아무 수나 두는 상대에게 지지 않고, 완벽한 상대와는 모두 비깁니다.
- 탐색 200번으로 다시 평가하면(`--eval-only --sims 200`) 완벽한 상대와 100판 모두 무승부, 지는 수는 9,105판 중 3판입니다.
- 신경망만 쓰면 지는 수가 아직 남습니다. 상대가 이상하게 둔 뒤의 판은 자기대국에서 잘 안 나와서 덜 배웁니다.
- 자기대국에서 처음 3수만 뽑던 설정보다 한 판 전체를 뽑는 지금 기본값이 낫습니다
  (같은 6분에 신경망만 89.3% → 94.4%, 탐색 50번 98.3% → 99.0%).

**더 큰 게임** (8×8 판, 선택 → 이동, 한 판에 20~30수 되는 체스 변형. 물리 코어 4개 CPU, GPU는 RTX 2080 Ti. 평가는 모두 PUCT 탐색)

| | 10분, 워커 1개 | 30분, 워커 8개 | 30분, 롤아웃 워밍업 10분 | GPU 60분 학습의 20분 시점 | 60분, GPU |
|---|---|---|---|---|---|
| 신경망 (`--blocks`, `--filters`) | 2, 32 | 2, 32 | 2, 32 | 6, 96 | 6, 96 |
| 자기대국 탐색 | PUCT 32번 | PUCT 32번 | PUCT 32번 | Gumbel 16번, `--value-mix 0.5` | Gumbel 16번, `--value-mix 0.5` |
| 한 국면 학습 횟수 (위 "손실") | 8.5번쯤 | 8.5번쯤 | 8.5번쯤 | 2.7번쯤 (`--steps 100`) | 2.7번쯤 (`--steps 100`) |
| 자기대국 | 1,472판 | 6,912판 | 7,168판 (롤아웃 2,048판) | 18,688판 | 57,088판 |
| 아무 수나 두는 상대 (탐색 32번, 60판) | 46승 3무 11패 | 51승 1무 8패 | 50승 2무 8패 | 58승 0무 2패 | 58승 0무 2패 |
| 롤아웃 AI (탐색 32번 대 50번, 60판) | 25승 6무 29패 | 21승 6무 33패 | 22승 10무 28패 | 32승 0무 28패 | 30승 0무 30패 |
| 롤아웃 AI (탐색 100번 대 200번, 60판) | 11승 33무 16패 | 14승 15무 31패 | 6승 28무 26패 | 26승 0무 34패 | 30승 0무 30패 |

- CPU 세 모델은 학습 없는 롤아웃 AI를 이기지 못합니다. 판을 4.7배 더 둬도, 롤아웃 AI가 둔 판으로 먼저 가르쳐도 롤아웃 AI 상대로는 나아지지 않았습니다.
  CPU 모델은 아래 꼼수를 막기 전에 학습하고 평가해서, 무승부는 대부분 학습용 반복 규칙으로 끊은 판입니다.
- GPU 모델은 롤아웃 AI보다 탐색을 적게 하고도 반반쯤 이깁니다. 아무 수나 두는 상대에게는 60판 중 58판을 이깁니다.
- 선공일 때 많이 집니다 (60분 모델, 32번 대 50번: 선공 8승 24패, 후공 22승 6패). 자기대국에서도 후공이 60.5%를 이기는 게임입니다.
  평가는 선공 32판, 후공 28판으로 나뉘어 AI에게 조금 불리합니다.
- 20분과 60분의 차이는 60판으로는 가려지지 않습니다 (한쪽으로 6판쯤은 운으로도 나옴). 새 판 정책 손실은 계속 내려갑니다 (20분 1.48 → 60분 1.31).
- 새 판 가치 손실은 "늘 0"보다 조금만 낮습니다 (마지막 25반복 평균 0.347 대 0.362). 승패는 거의 못 맞히고, 힘은 정책과 탐색에서 나옵니다.
- **꼼수를 막기 전에는** 선공이 자기 차례 안에서 기물 선택만 바꿔 같은 판을 세 번 만들어 혼자 무승부를 냈습니다 (아래 "대국 화면과 같은 규칙").
  그때 60분 모델은 롤아웃 AI와 60판 중 47~49판을 비겼고, 자기대국에서 끊긴 판이 128판 중 91판이라 가치 정답이 0으로 쏠렸습니다.
  막은 뒤에는 자기대국 57,088판 중 끊긴 판이 0판입니다.
- 10분 모델은 신경망만 쓰면 아무 수나 두는 상대에게 51.5%만 이깁니다. 힘의 대부분이 탐색에서 나옵니다.
- CPU에서는 신경망 계산이 가장 느립니다. 기본 크기(4, 64)는 한 반복(64판)에 74초, (2, 32)는 29초였습니다.
- GPU에서는 6×96 신경망으로도 분당 950판쯤 둡니다 (CPU 2×32, PUCT 32번은 230판). 탐색 횟수가 절반이기도 하고, 이때는 Node 쪽 게임 진행이 가장 느립니다.
- 워커 8개는 1개보다 분당 판 수가 1.5배쯤입니다. 물리 코어가 4개라 Node와 신경망 계산이 코어를 나눠 씁니다.

**자주 바꾸는 옵션** (`python trainer/train.py --help`에 전부 있음)

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--minutes` | 10 | 학습 예산. 이 시간이 지나면 반복을 멈추고 평가합니다 |
| `--games` | 100 | 반복마다 자기대국 판 수 |
| `--sims` | 50 | 한 수마다 탐색 횟수 (자기대국과 평가) |
| `--workers` | CPU 스레드 수 | 자기대국 워커(Node 프로세스) 수. `--games`를 나눠 둡니다 |
| `--parallel` | 64 | 워커마다 동시에 두는 판 수 |
| `--temp-moves` | 판의 자리 수 (30까지) | 자기대국에서 처음 몇 수를 방문 수에 비례해 뽑을지. 나머지는 가장 좋은 수 |
| `--max-moves` | 512 | 학습할 때 한 판의 최대 수(차례가 넘어간 횟수). 넘으면 무승부 (아래 "대국 화면과 같은 규칙") |
| `--blocks`, `--filters` | 4, 64 | 신경망 크기 (잔차 블록 수, 채널 수) |
| `--steps` | 100 | 반복마다 학습 걸음 수 (한 걸음에 `--batch`개 국면). 많으면 판을 외웁니다 (위 "손실") |
| `--window` | 20 | 최근 몇 반복의 판으로 학습할지 |
| `--rollout-sims` | 200 | 마지막 평가에서 둘 롤아웃 AI의 탐색 횟수. 0이면 안 둠 |
| `--warmup-minutes` | 0 | 처음 몇 분은 신경망 대신 롤아웃 AI끼리 둔 판으로 가르칩니다. 무작위 신경망끼리 둔 판보다 배울 게 많습니다 |
| `--warmup-sims` | 50 | 그때 롤아웃 AI의 탐색 횟수 |
| `--search` | `puct` | 자기대국 탐색. `gumbel`은 탐색이 적어도(16번 안팎) 학습이 되는 Gumbel AlphaZero입니다 |
| `--value-mix` | 0 | 가치 정답에 탐색이 낸 그 국면의 평가를 이만큼 섞습니다. 0이면 최종 승패만 씁니다 |
| `--snapshot-every` | 10 | 학습 기록: 몇 분마다 그때의 AI끼리 둔 판을 남길지. 0이면 남기지 않음 (아래 "학습 기록") |
| `--snapshot-games` | 2 | 스냅샷마다 AI끼리 둘 판 수 (8판까지) |
| `--device` | GPU가 있으면 `cuda` | |

## 브라우저에서 AI와 두기

학습한 신경망을 ONNX로 내보내 운영자 화면에서 올리면, 로비의 게임 창에 "AI와 두기"가 생깁니다.

```bash
python trainer/train.py games/tictactoe --export-onnx --play-sims 100
```

`trainer/runs/<게임 id>/model.pt`를 읽어 같은 폴더에 `model.onnx`와 `model.json`(관측과 행동의 모양, 탐색 횟수)을 씁니다.
운영자 화면(`/web/admin.html`)의 "AI 모델"에서 두 파일을 같이 골라 올립니다. 서버는 `DATA_DIR/ai/<게임 id>/`에 두고
(레포 게임과 올린 게임 모두), 같은 게임에 다시 올리면 바뀝니다. 지금은 난이도가 한 단계입니다.

- **모양이 같으면 예전 모델도 씁니다.** 관측 채널 이름, `rows`, `cols`, 특수 행동, 행동 수가 지금 게임 코드와 같아야 합니다.
  코드 버전은 달라도 됩니다 (규칙을 조금 고친 게임이면 약해질 뿐 둘 수는 있습니다). 내보낼 때(`train.py`), 올릴 때(서버),
  둘 때(브라우저) 세 번 봅니다. 모양이 다르면 다시 학습해야 합니다. 운영자 화면은 학습한 버전이 지금 버전과 같은지 보여 줍니다.
- **세기는 탐색 횟수**로 정합니다. `--play-sims`(기본 100, 1~2000)가 `model.json`의 `sims`가 됩니다.
  브라우저 AI는 행동마다 이만큼 탐색하므로, 기다리는 시간은 탐색 횟수 × 신경망 한 번 시간 × 한 차례의 행동 수입니다.
  Node에서 잰 WebAssembly 신경망 한 번은 스플체스(8×8, 6×96)가 12ms, 개척 오목(13×13, 6×96)이 18ms라서,
  100번이면 한 행동에 1.2초, 1.8초쯤입니다 (200번이던 때는 개척 오목 한 차례에 6~12초).
  시험할 때는 대국 화면 주소에 `&sims=1`처럼 붙여 바꿀 수 있습니다. 1이면 신경망의 첫 느낌대로 둡니다.
- 내보내기에는 `onnx`, `onnxscript`가, 내보낸 모델이 PyTorch와 같은 값을 내는지 보는 테스트에는 `onnxruntime`이 필요합니다
  (`requirements.txt`에 있음).

### AI 만들기 요청 (제작자 → 운영자)

1. 제작자가 내 프로필의 "내가 올린 게임"에서 **AI 만들기**를 누르면 그때의 코드 버전으로 요청이 생깁니다 (계정마다 한 번에 하나).
   기다리는 동안은 거둘 수 있습니다.
2. 운영자 화면의 **AI 요청**에서 **코드 받기**를 누르면 요청한 버전의 코드가 `<게임>-<버전>.zip`으로 받아지고 요청이 "학습 중"이 됩니다.
   zip에는 `<게임>/` 폴더 안에 코드와 `listing.json`이 있습니다. 코드 파일이 그대로라 `train.py`가 계산하는 버전이 사이트의 버전과 같습니다.
3. 압축을 풀어 학습하고 내보냅니다. **올린 게임의 코드를 내 컴퓨터에서 돌리는 것**이니 아래 "남은 일"의 격리를 보세요.

   ```bash
   python trainer/train.py <풀어 둔 폴더>/<게임> --minutes 60
   python trainer/train.py <풀어 둔 폴더>/<게임> --export-onnx
   ```

4. 운영자 화면의 **AI 모델**에서 `model.onnx`, `model.json`, `snapshots.json`을 같이 골라 올리면 요청이 끝나고(done)
   제작자의 프로필에 "AI: 있음"과 학습 기록 링크가 생깁니다. 학습할 수 없는 게임이면 이유를 적어 **반려**합니다 (제작자에게 보임).

### 학습 기록 (스냅샷)

`train.py`는 학습 전과 `--snapshot-every`분마다, 그리고 끝날 때 그때의 신경망으로 AI끼리 `--snapshot-games`판을 둬서
`trainer/runs/<게임 id>/snapshots.json`에 남깁니다 (`selfplay.js`의 `showcase`). 스냅샷마다 앞 스냅샷부터의 자기대국 통계
(선공·후공 승, 무승부, 되풀이로 끊은 판, 평균 수)와 마지막 평가(무작위 상대, 완전 탐색 상대, 정답 수 일치)가 같이 있습니다.
`--resume`으로 이어 학습하면 기록도 이어집니다. 첫 판은 가장 좋은 수만, 다음 판부터는 처음 두 수를 뽑아서 둡니다.

운영자가 모델과 같이 올리면(`PUT /api/admin/ai/<게임>/training`, 학습 기록만 올려도 됨) 제작자가 학습 기록 화면
(`/web/training.html?game=<게임>`)에서 봅니다. 판을 누르면 다시보기 화면에서 한 수씩 볼 수 있습니다.
학습이 되고 있는지, AI가 규칙의 구멍이나 꼼수(한쪽만 이김, 같은 판 되풀이)를 찾았는지, 게임 코드에 오류가 있는지 보려는 것입니다.
게임의 허점이 드러날 수 있어 **게임을 올린 사람과 운영자만** 봅니다. 서버는 2 MB, 스냅샷 40개, 스냅샷마다 8판, 판마다 행동 4,000개까지 받습니다.

**어디서 무엇이 도나**

```
대국 화면 (web/ai.js)
  ├─ 실행기 iframe 안 Worker (web/runner/host.js): 게임 코드 + env.js + mcts.js
  │    think: 신경망이 필요한 국면의 관측(float32)을 내놓고 멈춤 → answer: 정책·가치를 받아 이어서 탐색 → 고른 수
  └─ 사이트 Worker (web/ai-net.js): onnxruntime-web(WebAssembly)으로 model.onnx 계산
```

탐색은 `play()`를 수백 번 부르므로 게임 코드 옆(실행기)에서 돕니다. 실행기의 CSP는 WebAssembly와 네트워크를 막는데,
이것을 넓히지 않고 신경망만 밖의 사이트 Worker에서 돌립니다. 둘 사이에는 관측 배열과 정책·가치 숫자만 오가고,
실행기 호출 하나하나는 그대로 시간 제한(3초)을 받습니다.

**관측이 학습 때와 같은지**: 사이트가 이 폴더의 `env.js`, `mcts.js`를 그대로 내보내 실행기가 불러옵니다 (Go 서버의 `site.modules`).
[browser.test.js](browser.test.js)가 실행기의 탐색과 학습 쪽 탐색이 같은 관측을 같은 순서로 내고 같은 수를 고르는지 봅니다.

onnxruntime-web은 `web/vendor/package.json`의 고정 버전을 받아 씁니다. 레포에는 넣지 않습니다.

```bash
npm --prefix web/vendor ci
```

도커 이미지는 빌드할 때 받습니다. 서버는 그중 WebAssembly판 세 파일만 내보냅니다 (`site.vendorFiles`).

## 구조

게임 코드와 MCTS는 Node에서, 신경망은 Python(PyTorch)에서 돕니다. 탐색은 한 수마다 `play()`를 수백 번 부르기 때문에
게임 코드 옆에 두고, 여러 판이 낸 국면을 모아(batch) 한 번에 신경망에 넣습니다.
Node 워커는 `--workers`개를 띄우고, 신경망 계산 부탁은 모든 워커 것을 모아 계산합니다. 신경망은 한 번 부를 때 드는 시간이 커서
묶음이 클수록 빠르기 때문입니다.

| 파일 | 하는 일 |
|---|---|
| [env.js](env.js) | 게임 어댑터. 관측, 행동 번호, 둘 수 있는 행동, 결과. 브라우저 AI도 이 파일을 씁니다 |
| [mcts.js](mcts.js) | PUCT 탐색, 디리클레 잡음, 수 고르기, 학습 없는 롤아웃 AI. Node 전용 API를 안 써서 브라우저 AI에서도 씁니다 |
| [solve.js](solve.js) | 작은 게임의 완전 탐색 (확정 결론, 채점용 완벽한 상대) |
| [selfplay.js](selfplay.js) | 자기대국 워커. `train.py`와 stdin/stdout으로 이야기합니다 (메시지 형식은 파일 맨 위) |
| [net.py](net.py) | 완전 합성곱 정책·가치 신경망 (보드 크기와 무관한 구조) |
| [train.py](train.py) | 학습 반복, 평가, 체크포인트, ONNX 내보내기 |
| [load.js](load.js) | 게임 폴더 불러오기 (`listing.json`의 완전 번역 언어로 `result()`, `view()`를 부름) |

테스트는 Node 쪽(어댑터, 완전 탐색, MCTS, 브라우저 AI)과 Python 쪽(신경망 모양, 워커 메시지, ONNX 내보내기)이 따로 있습니다.

```bash
npm --prefix trainer test
python -m unittest discover -s trainer
```

**관측** (`[채널][rows][cols]`): 둘 차례인 쪽의 `view()`를 채널로 펼칩니다.

| 채널 | 내용 |
|---|---|
| 기물 | 기물 이름마다 한 채널 (`pieces`. `'xo'`는 2개, `'go-stones'`는 2개, `'chess'`는 12개) |
| 표시 | `marks`의 종류마다 한 채널 (`dot`, `ring`, `last-move`, `danger`, `ghost`, `blocked`, `frame`) |
| 칠한 칸 | `tint`의 색이 0, 1, 그 밖의 색 |
| 숫자 | `text`의 숫자 (만칼라의 씨앗 수 같은 것). 숫자가 아니면 1 |
| 두는 쪽 | 후공 차례면 전부 1. 기물 이름은 절대값이라 누가 두는지를 따로 알려 줍니다 |
| `observe()` | 판에 안 보이는 정보 (게임이 줄 때만) |

**행동**: 클릭 `rows × cols`개(번호 = `row * cols + col`) 뒤에 `specialActions`가 붙습니다.
둘 수 있는 행동은 `legal()`의 행동 중에서, `legal()`이 없으면 모든 행동 중에서 **실제로 상태를 바꾸는 것**만입니다.
상태를 바꿨는지는 대국 화면과 같은 해시로 봅니다.

**대국 화면과 같은 규칙**: `play()`가 오류를 던지면 무시된 행동, `result()`가 오류면 진행 중으로 봅니다.
**수는 차례가 넘어간 행동**입니다 (`turn()`이 다른 값이 되거나 판이 끝남). 기물 고르기처럼 차례가 그대로인 행동은
수가 아니고, 둔 수가 `maxActions`에 이르면 무승부입니다. 선택 → 이동처럼 같은 플레이어가 연달아 둬도 되도록,
탐색의 가치는 "한 수마다 부호 뒤집기" 대신 선공 기준으로 쌓고 노드마다 둘 차례인 쪽에서 봅니다.

**한 차례 안에서 이미 나온 판으로는 돌아가지 못합니다.** 기물을 골랐다 바꾸기를 되풀이하는 것은 아무것도 안 한 것과 같아서
무시된 행동으로 봅니다 (대전 서버도 그렇게 셉니다). 막아도 실제로 둘 수 있는 수는 하나도 줄지 않습니다.

학습할 때만 무승부 규칙을 하나 더 씁니다. 차례가 시작된 판이 세 번 나오거나 `--max-moves`수를 두면 무승부로 끝냅니다.
양쪽이 같은 판을 오가면 `maxActions`까지 가서 학습이 아주 느려지기 때문입니다. 반복은 양쪽이 함께 만들어야 하므로
이기고 있는 쪽은 피하도록 배웁니다. 이렇게 끝난 판 수는 `(cut N)`으로 찍습니다.

예전에는 차례 중간의 판(기물을 고른 상태)도 셌습니다. 그래서 선공이 자기 차례에 고르기만 바꿔 혼자 무승부를 만들 수 있었고,
스플체스 학습에서 AI가 이 꼼수를 배웠습니다 (위 "더 큰 게임").

## 학습할 수 있는 게임

- **탐색은 `turn()`으로 판마다 누가 둘 차례인지 압니다.** `turn()`은 모든 게임의 필수 함수이고,
  등록 검사가 `play()`와 맞는지 확인합니다. 두 사람이 동시에 두는 게임은 이 방식으로 학습할 수 없습니다.
- **`legal()`이 있으면 빠릅니다.** 그 목록을 믿고, 각 수는 탐색이 처음 고를 때만 둬 봅니다.
  목록에 있지만 무시되는 행동은 그때 지웁니다. `legal()`이 없으면 국면마다 모든 행동을 미리 둬 봅니다.
- **판에 안 보이는 정보는 `observe()`로** 알려 줘야 AI가 압니다. 바둑의 패 자리, 체스의 캐슬링 권리, 바둑의 연속 넘김 같은 것입니다.
- **완전 정보 게임**을 전제로 합니다. 둘 차례인 쪽의 화면을 관측으로 씁니다.
- 시작 판이 시드에 따라 다른 게임은 자기대국마다 다른 시드를 씁니다. 완전 탐색은 시드 0의 시작 판만 봅니다.

## 남은 일

1. **AI 만들기 대기열의 나머지**: 요청, 코드 받기, 반려, 모델과 학습 기록 올리기는 됩니다 (위 "AI 만들기 요청").
   학습 명령을 한 번에 돌리는 스크립트(zip 풀기 → 학습 → 내보내기)와 요청이 왔을 때 운영자에게 알리기는 아직입니다.
2. **격리**: 지금은 게임 코드를 이 프로세스에서 그대로 돌립니다. 올린 게임을 학습할 때는 네트워크가 없고
   시간·메모리를 제한한 컨테이너 안에서 돌려야 합니다 (Node의 `vm`은 보안 경계가 아님). 운영자 컴퓨터에서 학습할 때도 같습니다.
3. **서버에서 학습**: 대기열을 사람 대신 학습할 때만 켜는 워커 VM(Spot)이 받아 학습하고 모델을 올립니다.
   코드 버전이 바뀌어 관측 모양이 달라지면 다시 학습합니다.
   운영 VM(`e2-small`)에서는 학습하지 않습니다. 대국 서버가 느려지고 메모리가 모자랍니다.
4. **난이도와 밸런스**: 체크포인트 × 탐색 횟수로 난이도 여러 단계 (지금은 한 단계), AI끼리 둔 결과로 선공 승률 리포트.
5. **학습 효율**: 같은 판의 신경망 계산 다시 쓰기, 게임이 대칭을 알려 주면 대칭으로 데이터 늘리기,
   끝난 판의 화면을 칸마다 맞히는 보조 정답 (땅, 칠하기류 게임).
6. **유명한 게임**: 학습하지 않고 기존 엔진(KataGo, Stockfish 등)을 연결합니다.
