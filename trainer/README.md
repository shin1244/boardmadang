# AI 학습

업로드된 창작 게임으로 AI를 자동 학습시키는 파이프라인입니다. 설계 배경은
[docs/architecture.md](../docs/architecture.md#ai-학습-예정)에 있습니다.

지금은 **첫 단계**입니다. 게임 폴더 하나를 내 컴퓨터에서 학습시키고, 작은 게임이면 완전 탐색한 정답으로 채점합니다.
브라우저에서 AI와 두기, 서버에서 학습하기는 아직입니다 ([남은 일](#남은-일)).

## 방식: AlphaZero (신경망 + MCTS 자기대국)

PPO는 쓰지 않습니다. 승패 하나만 보상으로 받고 수읽기를 못 해서 바둑·체스 같은 게임에서 약하기 때문입니다.
AlphaZero는 같은 설정으로 여러 게임을 학습시킬 수 있는 범용 방식이고, 작은 게임에도 그대로 통합니다.

```
자기대국 (MCTS로 매 수 탐색)
  → (국면, 탐색이 고른 수의 분포, 최종 승패) 를 학습 데이터로 저장
  → 신경망 학습: 정책(어디에 둘지) + 가치(누가 유리한지)
  → 새 신경망으로 다시 자기대국
```

## 해 보기

Node 18 이상과 Python 3.10 이상이 필요합니다. 틱택토 크기는 CPU로 충분합니다.

```bash
pip install -r trainer/requirements.txt
python trainer/train.py games/tictactoe --minutes 5
```

반복마다 자기대국 결과와 손실을, 5번마다 평가를 찍습니다. 결과는 `trainer/runs/<게임 id>/`에 남습니다 (깃에는 안 올라감).

- `model.pt`: 마지막 신경망과 설정. `--resume`으로 이어서 학습합니다.
- `log.jsonl`: 반복마다 자기대국 통계, 손실, 평가

```
tictactoe: 3x3 board, 9 actions, 14 input channels, lang ko, device cpu
solved exactly (16168 positions): draw with perfect play
iter   1  first/second/draw 65/20/15  moves 6.8  loss p 1.554 v 0.336  buffer 682  10s
...
iter  41  first/second/draw 22/2/76  moves 8.4  loss p 0.836 v 0.110  buffer 16570  361s
final evaluation
  vs random  first W/D/L 19/1/0  second 15/5/0
  vs perfect first W/D/L 0/20/0  second 0/20/0
  best move (9105 positions)
    policy 94.4% (missed wins 438, blunders 74)
    search 99.0% (missed wins 84, blunders 7)
```

**평가**
- `vs random`: 아무 수나 두는 상대와 둔 결과. AI가 선공일 때와 후공일 때의 승/무/패입니다.
- `vs perfect`: 완전 탐색한 정답대로 두는 상대(가장 좋은 수 중 아무거나). 틱택토라면 모두 무승부가 나와야 완벽합니다.
- `vs rollout`: 학습 없는 롤아웃 AI(`--rollout-sims`번 탐색. 각 수 뒤를 아무렇게나 끝까지 둬 보고 고름). 마지막 평가에서만 둡니다.
  신경망 없이 공짜로 만드는 AI라서, 학습한 AI는 적어도 이 상대를 이겨야 학습한 보람이 있습니다.
- `best move`: 가장 좋은 수가 따로 있는 모든 판에서 AI가 그 수를 고르는 비율. `policy`는 신경망만, `search`는 탐색까지 한 것입니다.
  틀린 수는 이길 판을 비기거나 진 것(`missed wins`)과 지지 않을 판을 진 것(`blunders`)으로 나눕니다.
  상대가 엉망으로 둔 뒤의 판까지 모두 셉니다.
- `vs perfect`와 `best move`는 판 수가 상한(`--solve-limit`, 5만) 아래라 완전 탐색이 되는 게임에만 나옵니다.
- AI가 진 판은 `lost to …: actions …`로 행동 번호를 찍습니다.
- 학습한 신경망을 다시 평가하려면 `--eval-only`를 씁니다. `--sims`를 바꾸면 생각 시간에 따라 얼마나 강해지는지 봅니다.

**틱택토 결과** (CPU 8코어, 기본값으로 6분)
- 아무 수나 두는 상대에게 지지 않고, 완벽한 상대와는 모두 비깁니다.
- 탐색 200번으로 다시 평가하면(`--eval-only --sims 200`) 완벽한 상대와 100판 모두 무승부, 지는 수는 9,105판 중 3판입니다.
- 신경망만 쓰면 지는 수가 아직 남습니다. 상대가 이상하게 둔 뒤의 판은 자기대국에서 잘 안 나와서 덜 배웁니다.
- 자기대국에서 처음 3수만 뽑던 설정보다 한 판 전체를 뽑는 지금 기본값이 낫습니다
  (같은 6분에 신경망만 89.3% → 94.4%, 탐색 50번 98.3% → 99.0%).

**더 큰 게임** (8×8 판, 선택 → 이동, 한 판 50수쯤 되는 체스 변형. 물리 코어 4개 CPU, GPU는 RTX 2080 Ti. 평가는 모두 PUCT 탐색)

| | 10분, 워커 1개 | 30분, 워커 8개 | 30분, 롤아웃 워밍업 10분 | 20분, GPU |
|---|---|---|---|---|
| 신경망 (`--blocks`, `--filters`) | 2, 32 | 2, 32 | 2, 32 | 6, 96 |
| 자기대국 탐색 | PUCT 32번 | PUCT 32번 | PUCT 32번 | Gumbel 16번, `--value-mix 0.5` |
| 자기대국 | 1,472판 | 6,912판 | 7,168판 (롤아웃 2,048판) | 11,520판 |
| 아무 수나 두는 상대 (탐색 32번, 60판) | 46승 3무 11패 | 51승 1무 8패 | 50승 2무 8패 | 32승 26무 2패 |
| 롤아웃 AI (탐색 32번 대 50번, 60판) | 25승 6무 29패 | 21승 6무 33패 | 22승 10무 28패 | 17승 33무 10패 |
| 롤아웃 AI (탐색 100번 대 200번, 60판) | 11승 33무 16패 | 14승 15무 31패 | 6승 28무 26패 | 9승 46무 5패 |

- CPU 세 모델은 학습 없는 롤아웃 AI를 이기지 못합니다. 판을 4.7배 더 둬도, 롤아웃 AI가 둔 판으로 먼저 가르쳐도 롤아웃 AI 상대로는 나아지지 않았습니다.
- GPU 모델은 처음으로 롤아웃 AI에게 진 판보다 이긴 판이 많습니다. 대신 무승부(반복 규칙으로 끊은 판)가 많고, 아무 수나 두는 상대도 잘 끝내지 못합니다. 지지 않는 법은 배웠지만 이기는 법은 덜 배운 모습입니다. 신경망 크기와 탐색 방법을 함께 바꿔서 어느 쪽 덕인지는 아직 모릅니다.
- 10분 모델은 신경망만 쓰면 아무 수나 두는 상대에게 51.5%만 이깁니다. 힘의 대부분이 탐색에서 나옵니다.
- CPU에서는 신경망 계산이 가장 느립니다. 기본 크기(4, 64)는 한 반복(64판)에 74초, (2, 32)는 29초였습니다.
- GPU에서는 6×96 신경망으로도 분당 560판쯤 둡니다 (CPU 2×32, PUCT 32번은 230판). 탐색 횟수가 절반이기도 하고, 이때는 Node 쪽 게임 진행이 가장 느립니다.
- 워커 8개는 1개보다 분당 판 수가 1.5배쯤입니다. 물리 코어가 4개라 Node와 신경망 계산이 코어를 나눠 씁니다.
- 무승부는 대부분 학습용 반복 규칙으로 끊은 판입니다.

**자주 바꾸는 옵션** (`python trainer/train.py --help`에 전부 있음)

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--minutes` | 10 | 학습 예산. 이 시간이 지나면 반복을 멈추고 평가합니다 |
| `--games` | 100 | 반복마다 자기대국 판 수 |
| `--sims` | 50 | 한 수마다 탐색 횟수 (자기대국과 평가) |
| `--workers` | CPU 스레드 수 | 자기대국 워커(Node 프로세스) 수. `--games`를 나눠 둡니다 |
| `--parallel` | 64 | 워커마다 동시에 두는 판 수 |
| `--temp-moves` | 판의 자리 수 (30까지) | 자기대국에서 처음 몇 수를 방문 수에 비례해 뽑을지. 나머지는 가장 좋은 수 |
| `--max-moves` | 512 | 학습할 때 한 판의 최대 행동 수. 넘으면 무승부 (아래 "대국 화면과 같은 규칙") |
| `--blocks`, `--filters` | 4, 64 | 신경망 크기 (잔차 블록 수, 채널 수) |
| `--rollout-sims` | 200 | 마지막 평가에서 둘 롤아웃 AI의 탐색 횟수. 0이면 안 둠 |
| `--warmup-minutes` | 0 | 처음 몇 분은 신경망 대신 롤아웃 AI끼리 둔 판으로 가르칩니다. 무작위 신경망끼리 둔 판보다 배울 게 많습니다 |
| `--warmup-sims` | 50 | 그때 롤아웃 AI의 탐색 횟수 |
| `--search` | `puct` | 자기대국 탐색. `gumbel`은 탐색이 적어도(16번 안팎) 학습이 되는 Gumbel AlphaZero입니다 |
| `--value-mix` | 0 | 가치 정답에 탐색이 낸 그 국면의 평가를 이만큼 섞습니다. 0이면 최종 승패만 씁니다 |
| `--device` | GPU가 있으면 `cuda` | |

## 구조

게임 코드와 MCTS는 Node에서, 신경망은 Python(PyTorch)에서 돕니다. 탐색은 한 수마다 `play()`를 수백 번 부르기 때문에
게임 코드 옆에 두고, 여러 판이 낸 국면을 모아(batch) 한 번에 신경망에 넣습니다.
Node 워커는 `--workers`개를 띄우고, 신경망 계산 부탁은 모든 워커 것을 모아 계산합니다. 신경망은 한 번 부를 때 드는 시간이 커서
묶음이 클수록 빠르기 때문입니다.

| 파일 | 하는 일 |
|---|---|
| [env.js](env.js) | 게임 어댑터. 관측, 행동 번호, 둘 수 있는 행동, 결과 |
| [mcts.js](mcts.js) | PUCT 탐색, 디리클레 잡음, 수 고르기, 학습 없는 롤아웃 AI. Node 전용 API를 안 써서 브라우저 AI에서도 씁니다 |
| [solve.js](solve.js) | 작은 게임의 완전 탐색 (확정 결론, 채점용 완벽한 상대) |
| [selfplay.js](selfplay.js) | 자기대국 워커. `train.py`와 stdin/stdout으로 이야기합니다 (메시지 형식은 파일 맨 위) |
| [net.py](net.py) | 완전 합성곱 정책·가치 신경망 (보드 크기와 무관한 구조) |
| [train.py](train.py) | 학습 반복, 평가, 체크포인트 |
| [load.js](load.js) | 게임 폴더 불러오기 (`listing.json`의 완전 번역 언어로 `result()`, `view()`를 부름) |

테스트는 Node 쪽(어댑터, 완전 탐색, MCTS)과 Python 쪽(신경망 모양, 워커 메시지)이 따로 있습니다.

```bash
npm --prefix trainer test
python -m unittest discover -s trainer
```

**관측** (`[채널][rows][cols]`): 둘 차례인 쪽의 `view()`를 채널로 펼칩니다.

| 채널 | 내용 |
|---|---|
| 기물 | 기물 이름마다 한 채널 (`pieces`. `'xo'`는 2개, `'go-stones'`는 2개, `'chess'`는 12개) |
| 표시 | `marks`의 종류마다 한 채널 (`dot`, `ring`, `last-move`, `danger`, `ghost`, `blocked`, `frame`) |
| 칠한 칸 | `tint`의 색이 0, 1, 그 밖의 색 |
| 숫자 | `text`의 숫자 (만칼라의 씨앗 수 같은 것). 숫자가 아니면 1 |
| 두는 쪽 | 후공 차례면 전부 1. 기물 이름은 절대값이라 누가 두는지를 따로 알려 줍니다 |
| `observe()` | 판에 안 보이는 정보 (게임이 줄 때만) |

**행동**: 클릭 `rows × cols`개(번호 = `row * cols + col`) 뒤에 `specialActions`가 붙습니다.
둘 수 있는 행동은 `legal()`의 행동 중에서, `legal()`이 없으면 모든 행동 중에서 **실제로 상태를 바꾸는 것**만입니다.
상태를 바꿨는지는 대국 화면과 같은 해시로 봅니다.

**대국 화면과 같은 규칙**: `play()`가 오류를 던지면 무시된 행동, `result()`가 오류면 진행 중으로 봅니다.
상태를 바꾼 행동이 `maxActions`에 이르면 무승부입니다. 선택 → 이동처럼 같은 플레이어가 연달아 둬도 되도록,
탐색의 가치는 "한 수마다 부호 뒤집기" 대신 선공 기준으로 쌓고 노드마다 둘 차례인 쪽에서 봅니다.

학습할 때만 무승부 규칙을 하나 더 씁니다. 같은 판이 세 번 나오거나 `--max-moves`번 두면 무승부로 끝냅니다.
선택 → 이동인 게임에서 고를 기물만 계속 바꾸며 맴돌면 `maxActions`까지 가서 학습이 아주 느려지기 때문입니다.
이렇게 끝난 판 수는 `(cut N)`으로 찍습니다.

## 학습할 수 있는 게임

- **탐색은 `turn()`으로 판마다 누가 둘 차례인지 압니다.** `turn()`은 모든 게임의 필수 함수이고,
  등록 검사가 `play()`와 맞는지 확인합니다. 두 사람이 동시에 두는 게임은 이 방식으로 학습할 수 없습니다.
- **`legal()`이 있으면 빠릅니다.** 그 목록을 믿고, 각 수는 탐색이 처음 고를 때만 둬 봅니다.
  목록에 있지만 무시되는 행동은 그때 지웁니다. `legal()`이 없으면 국면마다 모든 행동을 미리 둬 봅니다.
- **판에 안 보이는 정보는 `observe()`로** 알려 줘야 AI가 압니다. 바둑의 패 자리, 체스의 캐슬링 권리, 바둑의 연속 넘김 같은 것입니다.
- **완전 정보 게임**을 전제로 합니다. 둘 차례인 쪽의 화면을 관측으로 씁니다.
- 시작 판이 시드에 따라 다른 게임은 자기대국마다 다른 시드를 씁니다. 완전 탐색은 시드 0의 시작 판만 봅니다.

## 남은 일

1. **브라우저에서 AI와 대국**: 신경망을 ONNX로 내보내고, `mcts.js`를 실행기 Worker에서 게임 코드 옆에 돌립니다
   (신경망은 onnxruntime-web). 대전 서버는 계속 게임 코드를 돌리지 않습니다.
2. **서버에서 학습**: 제작자가 "AI 만들기"를 누르면 대기열에 넣고, 학습할 때만 켜는 워커 VM(Spot)이 받아 학습한 뒤
   결과를 게임 버전 옆에 저장합니다. 코드 버전이 바뀌면 다시 학습합니다 (클리어 체크와 같은 원리).
   운영 VM(`e2-small`)에서는 학습하지 않습니다. 대국 서버가 느려지고 메모리가 모자랍니다.
3. **격리**: 지금은 게임 코드를 이 프로세스에서 그대로 돌립니다. 올린 게임을 학습할 때는 네트워크가 없고
   시간·메모리를 제한한 컨테이너 안에서 돌려야 합니다 (Node의 `vm`은 보안 경계가 아님).
4. **난이도와 밸런스**: 체크포인트 × 탐색 횟수로 난이도 여러 단계, AI끼리 둔 결과로 선공 승률 리포트.
5. **학습 효율**: 같은 판의 신경망 계산 다시 쓰기, 게임이 대칭을 알려 주면 대칭으로 데이터 늘리기,
   끝난 판의 화면을 칸마다 맞히는 보조 정답 (땅, 칠하기류 게임).
6. **유명한 게임**: 학습하지 않고 기존 엔진(KataGo, Stockfish 등)을 연결합니다.

## 예산과 제한
