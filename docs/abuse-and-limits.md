# 악용 방어와 제한값

업로드 기반 플랫폼에서 가장 흔한 공격은 **비싼 연산을 남이 마음대로 일으키게 하는 것**입니다.
원칙은 하나입니다.

> **게임의 크기가 비용을 정하게 두지 말고, 플랫폼이 정한 예산이 비용을 정하게 한다.**

## 어디가 공격받을 수 있나

| 곳 | 게임 코드를 실행하나 | 위험 |
|---|---|---|
| 대전 서버 (중계) | 아니요 (락스텝) | 없음. 어떤 게임이든 서버 부담은 같습니다 |
| 플레이어 브라우저 | 예 (Web Worker) | 상대 컴퓨터만 느려짐 → Worker 시간 제한, 넘으면 대국 무효 |
| 업로드 검사 | 예 (CPU, 수 초) | 샌드박스의 시간·메모리 제한으로 상한이 있음 |
| **AI 학습** | 예 (GPU, 수십 분~) | **비용의 대부분.** 아래 방어 대상 |
| 서버 측 결과 검증 (예정) | 예 (CPU) | 대국당 시간 상한 |

## 방어 1: 학습은 예산제

학습은 "강해질 때까지"가 아니라 **정해진 GPU 시간만큼만** 돌립니다.
경우의 수가 압도적인 게임이 올라와도 같은 비용으로 더 약한 AI가 나올 뿐, 비용은 늘지 않습니다.
남는 위험은 "업로드 수 × 게임당 예산"이고, 이건 방어 2로 막습니다.

## 방어 2: 업로드와 학습을 분리

**업로드 → 검사 통과하면 바로 사람끼리 대전 가능.** 학습은 조건을 채워야 대기열에 들어갑니다.

| 조건 | 효과 |
|---|---|
| 실제 플레이 수에 비례해 학습 예산 지급 (예: 서로 다른 유저가 20판 이상) | 아무도 안 하는 스팸 게임은 학습비가 0. 비용이 게임의 인기와 같이 감 |
| 계정당 학습 대기열 1개, 하루 업로드 수 제한 | 대량 업로드 차단 |
| 로그인 필수 (필요하면 추가 인증) | 계정을 계속 새로 만드는 우회를 어렵게 함 |
| 전체 일일 GPU 예산 상한 + GCP 예산 알림 | 최악의 경우에도 청구서에 상한이 있음 |
| 같은 게임 지문이면 학습 결과 재사용 | 이름만 바꾼 복제 게임을 여러 번 올려도 학습은 한 번 |

**MVP에서는 학습을 관리자 승인제로 합니다.** 자동 조건은 유저가 늘어 손으로 승인할 수 없을 때 붙입니다.

## 방어 3: 업로드 검사

GPU를 쓰기 전에 CPU 샌드박스에서 싸게 걸러냅니다. 이 검사는 MVP부터 둡니다.
무한 루프 게임 하나가 대전을 망치는 걸 막아주기 때문입니다.

```
업로드
 → 정적 검사: 코드 크기, rows·cols, 기물 종류 수, maxActions
 → 실행 검사 (시간·메모리 제한 샌드박스)
     · play() 실행 시간
     · 상태 JSON 크기
     · 결정성: 같은 시드·같은 행동을 두 번 재생해서 해시 비교
     · 종료: 랜덤 대국 수백 판이 전부 maxActions 안에 끝나는지 (상태를 바꾼 행동 기준)
 → 복잡도 측정: 랜덤 대국의 평균 선택지 수 × 평균 길이
     → "예상 복잡도: 9×9 바둑 수준", 예상 AI 실력을 제작자에게 표시 (거부 기준이 아님)
 → 지문: 고정 시드로 정해진 랜덤 행동을 둔 결과 화면들의 해시
     → 코드만 살짝 바꾼 복제 게임 식별
 → 통과 → 대전 오픈
```

복잡도는 **거부하는 데 쓰지 않습니다.** 큰 게임도 사람끼리 대전은 문제없기 때문입니다.
대신 "이 게임의 AI는 학습 예산 안에서 초급 수준까지 기대할 수 있습니다"처럼 기대치를 알려줍니다.

## 방어 4: 게임 코드의 직접 공격

| 공격 | 방어 |
|---|---|
| 무한 루프 | 호출마다 시간 제한. 넘으면 실격 |
| 남의 차례에 클릭 연타 (강제 무승부, 기록 부풀리기) | `maxActions`는 상태를 바꾼 행동만 셈. 무시된 행동이 상한을 넘으면 그 플레이어 패배 (`spam`), 연결당 초당 행동 수 제한 |
| 메모리 폭탄 (거대한 상태) | 상태 크기 상한, 샌드박스 메모리 상한 |
| 거대한 보드 | rows·cols 상한 |
| 검사 때만 빠르고 실제로는 느린 코드 | 대전·학습 중에도 같은 시간 제한 적용. 넘으면 대국 무효·학습 중단 |
| 네트워크·저장소 접근 | Web Worker + 별도 출처 iframe (architecture.md의 보안 참고) |

## 제한값 (초안)

실제로 게임을 몇 개 만들어 측정한 뒤 조정합니다.

| 항목 | 상한 |
|---|---|
| `rows`, `cols` | 32 |
| 기물 종류 수 | 32 |
| 게임 코드 크기 | 256 KB |
| `play()` 실행 시간 | 평균 2 ms, 1회 최대 50 ms |
| 상태 JSON 크기 | 64 KB |
| `maxActions` (상태를 바꾼 행동 수) | 2,000 |
| 무시된 행동 (대국당, 플레이어당) | 500 |
| 보내는 행동 (연결당) | 초당 20 |
| 하루 업로드 수 (계정당) | 5 |
| 게임당 학습 예산 | GPU 30분 (MVP는 관리자 승인 시에만) |
| 완전 탐색할 국면 수 | 1,000만 |
