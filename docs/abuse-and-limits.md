# 악용 방어와 제한값

업로드 기반 플랫폼에서 가장 흔한 공격은 **비싼 연산을 남이 마음대로 일으키게 하는 것**입니다.
원칙은 하나입니다.

> **게임의 크기가 비용을 정하게 두지 말고, 플랫폼이 정한 예산이 비용을 정하게 한다.**

## 어디가 공격받을 수 있나

| 곳 | 게임 코드를 실행하나 | 위험 |
|---|---|---|
| 대전 서버 (중계) | 아니요 (락스텝) | 없음. 어떤 게임이든 서버 부담은 같습니다 |
| 플레이어 브라우저 | 예 (Web Worker) | 상대 컴퓨터만 느려짐 → Worker 시간 제한, 넘으면 대국 무효 |
| 업로드 검사 | 예 (CPU, 수 초) | 샌드박스의 시간·메모리 제한으로 상한이 있음 |
| **AI 학습** | 예 (GPU, 수십 분~) | **비용의 대부분.** 아래 방어 대상 |
| 서버 측 결과 검증 (예정) | 예 (CPU) | 대국당 시간 상한 |

## 방어 1: 학습은 예산제

학습은 "강해질 때까지"가 아니라 **정해진 GPU 시간만큼만** 돌립니다.
경우의 수가 압도적인 게임이 올라와도 같은 비용으로 더 약한 AI가 나올 뿐, 비용은 늘지 않습니다.
남는 위험은 "업로드 수 × 게임당 예산"이고, 이건 방어 2로 막습니다.

## 방어 2: 업로드와 학습을 분리

**업로드 → 검사 통과하면 바로 사람끼리 대전 가능.** 학습은 조건을 채워야 대기열에 들어갑니다.

| 조건 | 효과 |
|---|---|
| 실제 플레이 수에 비례해 학습 예산 지급 (예: 서로 다른 유저가 20판 이상) | 아무도 안 하는 스팸 게임은 학습비가 0. 비용이 게임의 인기와 같이 감 |
| 계정당 학습 대기열 1개, 하루 업로드 수 제한 | 대량 업로드 차단 |
| 로그인 필수 (필요하면 추가 인증) | 계정을 계속 새로 만드는 우회를 어렵게 함 |
| 전체 일일 GPU 예산 상한 + GCP 예산 알림 | 최악의 경우에도 청구서에 상한이 있음 |
| 같은 게임 지문이면 학습 결과 재사용 | 이름만 바꾼 복제 게임을 여러 번 올려도 학습은 한 번 |

**MVP에서는 학습을 관리자 승인제로 합니다.** 자동 조건은 유저가 늘어 손으로 승인할 수 없을 때 붙입니다.

## 방어 3: 업로드 검사

GPU를 쓰기 전에 CPU 샌드박스에서 싸게 걸러냅니다. 이 검사는 MVP부터 둡니다.
무한 루프 게임 하나가 대전을 망치는 걸 막아주기 때문입니다.

지금은 등록창이 올린 사람의 브라우저에서 실행기 안에 [sdk/check.js](../sdk/check.js)를 돌립니다(아래의 실행 검사).
올린 사람이 결과를 바꿀 수 있으므로 서버는 파일 모양과 크기, 횟수만 지키고, 같은 검사를 서버 샌드박스에서 다시 하는 건 나중 일입니다.

```
업로드
 → 정적 검사: 코드 크기, rows·cols, 기물 종류 수, maxActions
 → 실행 검사 (시간·메모리 제한 샌드박스)
     · play() 실행 시간
     · 상태 JSON 크기
     · 결정성: 같은 시드·같은 행동을 두 번 재생해서 해시 비교
     · 종료: 랜덤 대국 수백 판이 전부 maxActions 안에 끝나는지 (차례가 넘어간 수 기준)
 → 복잡도 측정: 랜덤 대국의 평균 선택지 수 × 평균 길이
     → "예상 복잡도: 9×9 바둑 수준", 예상 AI 실력을 제작자에게 표시 (거부 기준이 아님)
 → 지문: 고정 시드로 정해진 랜덤 행동을 둔 결과 화면들의 해시
     → 코드만 살짝 바꾼 복제 게임 식별
 → 통과 → 대전 오픈
```

복잡도는 **거부하는 데 쓰지 않습니다.** 큰 게임도 사람끼리 대전은 문제없기 때문입니다.
대신 "이 게임의 AI는 학습 예산 안에서 초급 수준까지 기대할 수 있습니다"처럼 기대치를 알려줍니다.

## 방어 4: 게임 코드의 직접 공격

| 공격 | 방어 |
|---|---|
| 무한 루프 | 호출마다 시간 제한. 넘으면 실격 |
| 안쪽 Worker로 시간 제한 피하기 (함수는 바로 돌려주고 뒤에서 CPU 쓰기) | 실행기 Worker에서 게임 코드를 불러오기 전에 `Worker` 생성자를 지움 |
| 남의 차례에 클릭 연타 (강제 무승부, 기록 부풀리기) | `maxActions`는 둔 수(차례가 넘어간 행동)만 셈. 무시된 행동이 상한을 넘으면 그 플레이어 패배 (`spam`), 연결당 초당 행동 수 제한 |
| 내 차례에 기물 고르기만 바꾸며 맴돌기 (강제 무승부, 시간 끌기) | 고르기는 수가 아니라 `maxActions`에 안 셈. 이번 차례에 이미 나온 판으로 돌아가면 무시된 행동으로 셈 (`spam`) |
| 메모리 폭탄 (거대한 상태) | 상태 크기 상한, 샌드박스 메모리 상한 |
| 거대한 보드 | rows·cols 상한 |
| 검사 때만 빠르고 실제로는 느린 코드 | 대전·학습 중에도 같은 시간 제한 적용. 넘으면 대국 무효·학습 중단 |
| 네트워크·저장소 접근 | 출처 없는 샌드박스 iframe + Worker + CSP (architecture.md의 보안 참고) |

## 제한값 (초안)

실제로 게임을 몇 개 만들어 측정한 뒤 조정합니다.

| 항목 | 상한 |
|---|---|
| `rows`, `cols` | 32 |
| 기물 종류 수 | 32 |
| 게임 코드 크기 | 256 KB |
| `play()` 실행 시간 | 평균 2 ms, 1회 최대 50 ms |
| 상태 JSON 크기 | 64 KB |
| `maxActions` (차례가 넘어간 수) | 2,000 |
| 무시된 행동 (대국당, 플레이어당) | 500 |
| 보내는 행동 (연결당) | 초당 20 |
| 타이머 | 1~180분 (또는 없음) |
| 방 목록에서 방 올리기 | 방마다 1분에 한 번 |
| 방 목록에 보여줄 방, 관전 목록에 보여줄 대국 | 각 200 |
| 대국당 관전자 | 100 |
| 무승부 제안 | 거절당하면 행동이 하나 이상 오간 뒤에 다시 |
| 의견 | 계정만. 500자, 20줄. 한 사람이 15초에 하나 |
| 신고 | 계정만. 한 사람이 한 시간에 20번. 서로 다른 세 사람이 신고한 의견은 바로 가림 |
| 즐겨찾기(별) | 계정만 (게스트도 받으면 쿠키를 지워 가며 별 수를 부풀릴 수 있음). 한 계정은 한 게임에 별 하나. 탈퇴하면 그 계정의 별은 지움 |
| 올리는 zip | 300 KB, 파일 64개. 코드(`.js`, `.mjs`)는 합쳐서 256 KB, `listing.json` 1 MB, `thumbnail.json` 64 KB (정리한 뒤 32 KB) |
| 초안 | 한 계정이 한 시간에 30번 올리기. 계정마다 최근 3개만 남기고, 하루 지나면 지움 |
| 하루 등록 수 (계정당) | 5. 같은 게임을 다시 등록해도 셈. 그중 새 게임(처음 등록하는 id)은 하루 1개. 내 게임의 새 버전은 5번 안에서 자유. 하루는 지금부터 24시간 전까지 |
| 등록 정보만 고치기, 내리기, 다시 올리기 (계정당) | 한 시간에 30번. 하루 등록 수에는 세지 않음 |
| 제작자 클리어 기보 | 상태를 바꾼 행동 4,000개(`maxActions` 상한 2,000수에 기물 고르기가 하나씩 붙는 만큼)까지. 등록 본문은 등록 정보와 썸네일, 클리어 기보를 합쳐 1.6 MB 안팎 |
| 게임당 학습 예산 | GPU 30분 (MVP는 관리자 승인 시에만) |
| AI 모델 | 운영자만 올림. ONNX 16 MB까지, 게임마다 하나 (다시 올리면 바뀜) |
| AI 만들기 요청 | 계정만, 내가 올린 게임만. 한 계정에 안 끝난 요청은 하나, 그리고 일주일에 한 번 (마지막으로 요청한 때부터. 끝나거나 반려된 요청도 세고, 기다리는 동안 거둔 요청은 세지 않음). 운영자는 이 두 제한 없이 자기 게임을 요청함 (학습하는 사람이 운영자라서). 이미 그 버전으로 학습한 모델이 있으면 안 됨. 요청하기 전에 AI 실력은 게임마다 다르다는 안내에 동의해야 함 (화면에서만). 학습은 운영자가 직접 받아서 함 |
| AI 학습 기록 | 운영자만 올림. 2 MB, 스냅샷 40개, 스냅샷마다 8판, 판마다 행동 4,000개까지. 게임을 올린 사람과 운영자만 봄 |
| AI 탐색 횟수 | 한 수에 1~2,000번. 보는 사람의 브라우저에서 돌아서 서버 비용은 없음. 실행기 호출 하나하나는 대국과 같은 시간 제한 |
| 완전 탐색할 국면 수 | 1,000만 |
